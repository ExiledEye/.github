# Contributing Guidelines

Thank you for your interest in contributing! To maintain code quality and keep our workflows efficient, please review the following guidelines before getting started.

## How to Contribute

### 1. Reporting Bugs & Requesting Features
* **Check Existing Issues:** Before opening a new issue, search the repository to ensure it hasn't already been reported or discussed.
* **Use Templates:** Always use the provided issue templates and fill out all required fields (such as system specifications and reproduction steps).

### 2. Proposing Changes (Pull Requests)
* **Open an Issue First:** For significant changes or new features, please open an issue to discuss the implementation details before writing code.
* **Branch Standards:** Create a descriptive branch name (e.g., `feature/optimization-pass` or `fix/memory-leak`).
* **Keep PRs Focused:** A Pull Request should solve exactly one problem. Avoid bundling unrelated fixes or features together.
* **Code Style:** Ensure your code is clean, well-commented where necessary, and formatted according to standard conventions for the language used.

## Development Checklist
Before submitting a Pull Request, ensure you have:
- [ ] Tested the changes locally to confirm they work as intended.
- [ ] Verified that your changes do not introduce regressions or break existing functionality.
- [ ] Updated the relevant documentation (like the project README) if applicable.
